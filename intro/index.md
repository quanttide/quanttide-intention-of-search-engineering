# 量潮搜索工程意图

行动的起点：为什么做、做成什么样、哪些不做。

命题：把对外开放的知识库做成按次计费的搜索服务，在产生社会价值的基础上盈利。形式化表述为 $\max V$，约束 $R \ge C$：$V$ 为对外开放条件下问题被解决的期望量，$R$ 为搜索收入，$C$ 为成本。价值循环中的每一段给出该命题成立的条件。

系统按周期 $t$ 运行，状态 $x_t = (K_t, S_t)$：$K_t$ 为自有知识库（含推理机生成的结果），$S_t$ 为搜索结构。当前搜索需求为分布 $P_t$，查询 $q \sim P_t$。

## 开放

知识库的规模已经超出人工浏览的可用范围，检索因此成为智能系统不可缺少的能力。企业知识库以公开服务的形式对外开放，任何一方均可将其作为公开知识库使用。对外开放是 $V$ 产生的前提：$K_t$ 越准确、$S_t$ 越合理，被解决的问题越多。

## 反馈

每条查询产生行为样本 $b_t$（点击、改写、标记）。规模化的搜索行为构成对 $P_t$ 的采样，用于需求探测；为引擎增加各类标记能力后，系统具备独立的标记能力。状态更新规则为 $x_{t+1} = F(x_t, b_t)$。检索行为提供高频、精确的反馈，用于改进搜索结构与数据，两者协同治理。本域将大搜索作为搜索问题独立管理，而非作为知识库问题管理：搜索结构的组织方式及其与数据的协同治理属于本域职责。

## 判据

定义弯路成本 $d(q, x)$：AI 使用 $x$ 的检索结果求解 $q$ 时，实际路径长度与理想路径长度之差。示例：查询「教程的写作规范要求什么」，检索结果包含教程仓 CONTRIBUTING 时 $d \approx 0$；仅召回离散段落、需要额外两轮检索时 $d \approx 3$。「减少 AI 走弯路」即 $J(x) = \mathbb{E}_{q \sim P_t}[\,d(q, x)\,]$ 逐期下降，$J$ 下降是 $V$ 增长的手段。该判据从当前的搜索需求出发分析：$J$ 须在真实的 $P_t$ 上估计，而非在构造的测试集上。

## 元系统

交付物不是某个搜索算法，而是可以改进搜索算法的元系统：更新规则的参数 $\theta$ 亦随 $b_t$ 调整，$x_{t+1} = F_\theta(x_t, b_t)$。纯 RAG 为 $\theta$ 固定的特例，$J$ 不随周期下降，数据漂移时反而上升；其效果可能显得智能，对常见的企业需求并不有效。服务范围限定于 $K_t$ 与推理机生成的结果，$P_t$ 限定于企业需求，不提供公网通用检索，不与通用搜索同赛道。

## 变现与回流

搜索以 API 形式按搜索次数收费，$R_t = p N_t$，$p$ 为单价，$N_t$ 为调用次数；前台是搜索界面，靠这项收入独立运营，条件为 $R_t \ge C_t$。盈余 $R_t - C_t$ 重新投入开放与改进，构成闭环。系统不要求收敛到严格不动点；循环闭合的验收条件为存在稳定域 $X^*$：$x_t$ 长期处于 $X^*$，$J$ 低于纯 RAG 基线，且 $R \ge C$ 持续成立。

## 已知风险

索引随时间过时：$K_t$ 相对真实世界产生漂移，$J$ 随之上升。漂移无法被工程彻底根治，只能以监测、重建、增量更新控制其影响，当前优先级不高。对外开放引入非目标流量，$b_t$ 须甄别后使用，否则 $P_t$ 估计失真，$J$ 的改进方向随之偏离。
