# 量潮搜索工程意图

行动的起点：为什么做、做成什么样、哪些不做。

命题：把对外开放的知识库做成按次计费的搜索服务，在产生社会价值的基础上盈利。

## 价值循环

知识库的规模已经超出人工浏览的可用范围，检索因此成为智能系统不可缺少的能力。我方企业知识库作为公开服务对外开放，任何一方都能把它当作公开知识库使用——社会价值在这里产生。

用起来就产生搜索行为。规模化的搜索行为本身具有需求探测功能；为引擎增加各类标记能力后，它还具备独立的标记能力。检索行为提供高频、精确的反馈，用于改进搜索结构与数据——两者需要一同治理。本域把大搜索作为一个搜索问题独立管理，而不是作为一个知识库问题管理：搜索结构如何组织、如何与数据一同治理，是本域的职责。

改进只有一个判据：搜索能不能减少 AI 走弯路；能不能做到，从当前的搜索需求出发分析。

判据决定了要交付什么。目标不是某个搜索算法，而是一个可以改进搜索算法的元系统；它与数据同步演进，是一种提高使用效率的机制。纯 RAG 方案实现快但能力有限，不以元工程方法作为基础，效果可能显得智能，对常见的企业需求并不有效，撑不住这个判据。卖的是自有知识库与推理机器生成的结果，不是公网通用检索——不与通用搜索同赛道。

最后变现并回流。搜索以 API 形式按搜索次数收费，前台靠这项收入独立运营；收入反哺开放与改进，回到循环起点。

## 已知风险

索引会不断过时、更新速度太快，需要更细致的工程处理。此类问题都有根治办法，当前优先级不高。
